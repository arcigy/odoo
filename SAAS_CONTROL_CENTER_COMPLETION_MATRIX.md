## Current P0 blockers

1. Real Develop/Main base URLs are confirmed. Develop `/ready` now returns 200 JSON, but Develop `/metrics` returns 404 and Main `/ready` plus `/metrics` still return 200 SPA HTML. Two reconciled telemetry scrapes therefore remain unproven.
2. A read-only CapRover fingerprint audit proves separate `dev`/`prod` database schemas and object-storage prefixes, plus a dedicated Develop storage volume. Both services carry the same `DATABASE_URL` fingerprint. PostgreSQL then confirmed that the shared `kitchenapp` role owns both schemas and has SELECT/INSERT/UPDATE/DELETE across all 24 tables in each schema. Isolation is therefore configuration-only, not privilege-enforced; a future configuration error could reach Main. Live metrics credentials and ingestion remain intentionally disabled until the Arcigy task gives Develop a separately constrained database role/connection and passes an end-to-end mutation/isolation test.
3. Arcigy Develop/Main PostgreSQL pool/query, queue, dependency and automated backup producers are not yet deployed or reconciled; the environment-safe Prometheus adapter is ready. The separate Odoo control-plane backup automation does not substitute for this source evidence.
4. Two real Odoo backup records pass the complete no-write evidence path, but live `saas.backup.run` remains zero. Automated temporary-key transfer was stopped at the secret-handling boundary; the first live ingest requires a bot key established in an approved secret store without exposing it to commands, logs or chat.

The goal is not complete while any of these P0 items lacks evidence.
